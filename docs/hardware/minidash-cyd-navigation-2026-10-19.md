# CYD 0.3.1: смена экранов без дёрганой шторки

Ветка `feature/hardware-cyd-esp32`, ESP32-2432S028, версия `cyd-0.3.1-nav`.
Исходная сборка 0.3.0-light сохранена для отката. Main не меняется.

## Обратная связь и причина

19 октября пользователь подтвердил: «автояркость работает». Физическая работа
R21/AUTO теперь подтверждена пользователем. Численная калибровка ADC/lux не
заявляется. На приложенном фото Service Status видна версия cyd-0.3.0-light.
Пользователь одновременно сообщил о дёрганой и неудовлетворительной смене экранов.

Пиксельная шторка инвалидировала весь экран каждые 32 ms в течение 320/420 ms.
Одна передача 320×240×2 byte по SPI 20 MHz требует минимум 61,44 ms ещё без
рисования и накладных расходов. На ESP32 без PSRAM это не даёт плавного
32-ms кадра. Кроме того, сохранение last_screen меняло revision и повторно
запускало retheme/rebuild Custom даже при прежних теме и виджетах. Новая сцена
могла успеть отрисовать N/A и только через очередной 200-ms тик получить значения.

## Изменение

- `ui_screens.c`: на CYD не запускаются пиксельные transition timer и маски.
  Смена экрана обычная, без анимированной шторки. Три пиксельные темы, шрифты,
  рамки/индикаторы и CRT при старте сохранены. S3 сохраняет прежние переходы.
- `display_app.c`: под одним LVGL lock создаётся сцена и сразу заполняется
  текущим signal snapshot/диагностикой. Используется существующий heap snapshot
  UI task, без второй сцены или framebuffer. Это убирает преднамеренное ожидание
  200-ms модельного тика для первого наполнения обычной навигации.
- Сохранение last_screen/revision не запускает переоформление. Retheme нужен
  при изменении темы/палитры/языка; перестройка Custom — при изменении страницы
  или её виджетов. Остальные данные обновляются обычным модельным тиком.
- Факт показанной сцены публикуется после её подготовки, чтобы следующий проход
  не принимал уже выполненный переход за новый. Семантические touch команды,
  калибровка, геометрия hit targets и Wi-Fi policy не менялись.
- Добавлены журналы SCENE build_ms / FIRST_RENDER elapsed_ms. Первый измеряет
  подготовку сцены, второй — LVGL RENDER_READY от начала её подготовки. Это не
  замер «палец → фото LCD» и не доказательство отсутствия tearing.

Одновременно не менялись SPI 20 MHz, DMA buffer 16 строк, один активный LVGL
экран и бюджет RAM. Не добавлялись PSRAM, кэш нескольких сцен, CAN/UDS или
новые дублирующие renderer/engine. Auto brightness и schema 4 сохранены.

## Проверки

Windows, ESP-IDF 5.5.5 / GCC 14.2.0 / LVGL 9.5.0. Сборки:
`idf.py -C firmware -B build-cyd build` и `-B build-esp32_s3`.
Native: `ctest --test-dir core/build-cyd-check --output-on-failure`.
Аппаратно: app-only запись esptool на COM4 по 0x10000 с проверкой hash;
UART run/ui-test, переключения Pixel Arcade/Dungeon/Handheld, web-test, config-export,
sleep/wake, реальный reset, краткая навигация после reset. При переключении
проверяется отсутствие PIXEL_TRANSITION/PIXEL_COMPLETE, timer_absent=PASS и
populated=1 до первого RENDER_READY. Внешняя оценка плавности после исправления
агенту недоступна; её должен дать пользователь, наблюдающий LCD.

GCC измеренный путь UI task → apply_event → show_populated → diagnostics_snapshot:
2608 bytes + reserve 1024 < task stack 8192. Отдельная исходная проверка startup/NVS
также проходит. Это ограниченный набор путей, не полное доказательство call graph.
Общие native тесты — 12/12 PASS. Точные финальные аппаратные результаты и времена
приведены ниже и в поставляемом hardware-results.json.

## Использование и восстановление

Переключать экраны обычными сенсорными зонами/жестами. На CYD отдельного выбора
transition нет: эффект выключен для всех трёх pixel themes. S3 продолжает
использовать прежнюю анимацию. Wi-Fi запускается только вручную из Settings.

Обновление: app-only по 0x10000. NVS, калибровку и таблицу разделов не стирать.
Откат: сохранённый `minidash-cyd-rollback-0.3.0.bin` по тому же адресу. Формат
настроек одинаковый; AUTO и калибровка остаются. Полный возврат NerdMiner — по
исходному проверенному 4 MiB дампу, который хранится отдельно в прежней поставке.
Откат в этом сеансе не выполнялся; нет необходимости перезаписывать рабочую плату
для проверки инструкции. Приватные дампы, NVS и журналы не включаются в Git.

## Оставшиеся шаги

1. Физически оценить смену экранов после обновления: критерий — нет рваной
   шторки и вспышки N/A/пустых значений, касание даёт быструю понятную смену.
   Компоненты — LVGL scene lifetime и SPI flush; риск — ограничения SPI панели.
   Если заметна задержка/полоса, следующий источник доказательств — видео LCD,
   а не обещание высокой частоты кадров на основании UART.
2. Более долгий USB soak с навигацией/AUTO/Wi-Fi: проверить reset/WDT и heap
   на протяжении часов. Короткая приёмка не доказывает отсутствие долгих утечек.
3. CAN/питание — отдельный подтверждённый стенд и схема. CYD CAN TX/UDS выключены,
   подключение к автомобилю и внешнее питание в этой задаче не выполнялись.

Лицензия MIT проекта. Внешние игровые ассеты и код не копировались.
