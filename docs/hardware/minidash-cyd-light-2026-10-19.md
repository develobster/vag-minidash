# MiniDash CYD: читаемость и датчик света, 19 октября 2026

Версия: `cyd-0.3.0-light`, ветка `feature/hardware-cyd-esp32`.
Отдельная платформа CYD; main/integration не меняются. Никакого CAN/UDS TX.

## Причина и изменение текста

На фотографиях пользователя SSID переносился и строки Wi-Fi сближались;
в SERVICE STATUS длинное значение делило узкую строку с названием и обрезалось.
Теперь сервисные ячейки CYD имеют две строки полной ширины: заголовок сверху,
значение снизу. Высота строки 26 px учитывает реальную высоту русских/Mono
шрифтов 13 px, а не только число «10» в имени шрифта. Все 14 ячеек остаются
на экране. Заголовки, footer и значения Settings подбирают размер по измеренной
LVGL ширине. Кириллица и letter spacing учитываются. В Wi-Fi измеряется самая
длинная строка SSID/пароля/адреса, задан межстрочный интервал 5 px; QR не уменьшен.
Сервисный экран CYD больше не предлагает отправлять CAN/DTC запросы.

`ui_screens.c` использует текущую тему и её шрифт. Перестройка сервисной сетки
и адаптация подписей ограничены CYD; S3 сохраняет свою разметку. Телеметрические
карты, темы, конфигурация и диагностический движок переиспользованы.

## Датчик и алгоритм

Деталь R21 на третьем фото — фоторезистор. Схема изготовителя обозначает
GT36516 от GPIO34 к GND, R15 1 МОм к 3,3 В и R19 1 МОм к GND.
Источник: [схема ESP32-2432S028, лист 2, блок ADC](https://www.ardboard.com/downloads/ESP32_2432S028R_Schematics.pdf).
Дополнительная проверка назначения GPIO:
[NuttX board documentation](https://nuttx.apache.org/docs/12.9.0/platforms/xtensa/esp32/boards/esp32-2432S028/index.html).
Конкретную плату не прозванивали: схема — основание выбора входа, а не
электрическое доказательство каждой дорожки её ревизии.

`cyd_ambient.c` читает GPIO34/ADC1_CH6 в режиме oneshot, 12 bit, 0 dB.
ADC1 совместим с Wi-Fi. 0 dB выбран для слабого сигнала делителя с резистором
1 МОм; при очень тёмном датчике возможно насыщение — это соответствует
минимальной яркости. Это относительная оценка света, не измерение lux.
GPIO34 не конфликтует с TFT, touch или кандидатами CAN 22/27.

Раз в 250 ms усредняются 16 чтений. Существующая модель `md_brightness_t`
получила EMA 1/8 и гистерезис 3 процентных пункта. Чем выше ADC, тем темнее:
ADC <=300 соответствует 100%, ADC >=3300 — 15%, промежуточные значения
линейны. Подсветка GPIO21 меняется на один процент не чаще 20 ms. Переход от
15% к 100% занимает минимум 1,7 s при отсутствии задержек UI. Мелкий шум не
переключает яркость. В AUTO запуск идёт с 15% с последующим выходом на показание.
Сон выключает подсветку; датчик не включает её обратно. Ошибка чтения дольше
2 s возвращает сохранённую ручную яркость. Ноль — допустимое чтение ADC, не ошибка.

## Как использовать

- Settings → Brightness: цикл `10% … 100% → AUTO → 10%`. Обратное изменение:
  `10% → AUTO → 100%`. Сенсорный CHANGE меняет выбранное значение.
- Web Configurator: «Режим яркости» → «Авто · датчик света» или «Ручная».
  Поле ручной яркости остаётся сохранённым резервным уровнем.
- Сохранение использует существующий `platform.brightness_mode=2` и NVS,
  schema 4 не меняется. Измеренные уровни не записываются во flash.
- Wi-Fi включается вручную, после перезагрузки выключен. Предпросмотр и Cancel
  используют существующую транзакцию конфигурации.
- Консоль `brightness` явно возвращает ручной режим.

## Проверки и ограничения

Результаты окончательного аппаратного прогона приведены в поставке вместе с
`hardware-release.log` и `hardware-results.json`. Программная проверка границ
текста на 320×240 не заменяет фотографию экрана после исправления. Первая новая проверка
обнаружила две ошибки: неразрешённую LVGL layout-геометрию в тесте и фактическую
высоту RU/Mono 13 px; они исправлены, тест не ослаблялся.

До обновления UART показал `calibrated=1`, brightness=70, theme=11. Считана
резервная копия текущего NVS 0x9000/0x6000 и проверена esptool digest. Она
приватная и не включена в Git. Исходный полный дамп NerdMiner также сохранён,
его SHA-256 не менялся. Запись только приложения по 0x10000 сохраняет NVS.

Остаётся физическая проверка световой характеристики: закрыть R21 рукой,
затем осветить и убедиться, что яркость плавно уменьшается/увеличивается.
После перехода на 0 dB получены реальные чтения ADC 20…1017 (и ноль при
некоторых условиях), target 93% и output 96% на пути к нему. Это подтверждает
работу чтения и программной регулировки; условия освещения не контролировались
агентом. Ноль — допустимый нижний предел ADC, он сам по себе не доказывает
неисправность датчика. Делитель 1 МОм и разброс
LDR могут потребовать других порогов после наблюдения на этой плате. До такого
наблюдения не заявляется физическая проверка реакции на свет.

Также нужны новые фото Wi-Fi/Service Status и оценка читаемости пальцем/глазами.
S3 проверяется сборкой, реальная S3-плата в этом сеансе не испытывается.
Автомобильное питание, нагрев и CAN не проверялись.

## Обновление и восстановление

Обновление с MiniDash: `python -m esptool --chip esp32 --port COM4 --baud 460800
write-flash 0x10000 minidash-cyd-app.bin` (одной строкой). Не стирать flash/NVS.
Для отката на Pixel 0.2 использовать сохранённый предыдущий app по 0x10000;
`brightness_mode` уже существовал в schema 4. При необходимости перед откатом
выбрать ручную яркость: Pixel 0.2 не использует световой вход.
Полное восстановление NerdMiner — по инструкции из исходной поставки и
проверенному 4 MiB дампу. Приватный NVS MiniDash не является дампом NerdMiner.

Лицензия нового кода MIT проекта, внешние ассеты/код не копировались.

## Нагрузка встроенного HTTP теста

Первый прогон с пользовательской страницей из шести виджетов дал 59 PASS / 7 FAIL:
тест клонирует её на четыре страницы (24 виджета), оставляя в памяти ESP32
распечатанный запрос, пока тот же ESP32 разбирает его на сервере. Минимум heap
достиг 16 байт, cJSON не смог построить дерево и сервер вернул 400. Результат
сохранён как промежуточный неуспешный прогон, а не объявлен успешной проверкой.

В `ui_web.c` только CYD bench-клиент передаёт владение heap-строкой запроса:
после `esp_http_client_write` освобождает её до чтения ответа. Для повторного
запроса с устаревшей revision создаётся такая же строка заново. Проверки не
убраны, количество страниц/виджетов и ожидаемые HTTP статусы сохранены.
Настоящий телефон не держит свою копию запроса в памяти ESP32. Production HTTP
handlers не менялись, S3 продолжает использовать прежний `perform` путь.

При проверке перезапуска также исправлена прежняя миграция fixed-wiring NVS:
она безусловно назначала MANUAL даже сохранённому AUTO. На промежуточной
сборке это подтверждено реальным reset: HTTP 66/66 прошли, но чтение после
старта вернуло mode=1 вместо сохранённого mode=2. Теперь повышение
fixed→manual применяется только к `MD_BRIGHTNESS_FIXED`; уже сохранённый
AUTO не заменяется. Формат записи не меняется, S3 с ручной яркостью сохраняет
прежнее поведение. Подтверждение требует фактического reboot с AUTO, а не
только JSON encode/decode.

## Итоговые проверки окончательной сборки

Windows, ESP-IDF 5.5.5 / GCC 14.2.0, LVGL 9.5.0. Фактические команды:
`idf.py -C firmware -B build-cyd build`, аналогично `-B build-esp32_s3`;
`.venv/Scripts/python.exe -m unittest discover -s tests`;
`cmake --build core/build-cyd-check`, `ctest --test-dir core/build-cyd-check`;
Node `core/test_webui.cjs` с fixture native JSON binary.
Запись `esptool --chip esp32 --port COM4 --baud 460800 write-flash 0x10000`
с hash verification. UART: `run`, `ui-test`, `web-test`, `status`, `config-export`,
локальные Settings/plus/minus, sleep/wake; реальный reset через RTS.

|---|---|
| CYD build / S3 regression build | PASS / PASS, без compiler warnings |
| Python / native CTest | 229 tests, 1 Windows AF_CAN skip / 12 из 12 PASS |
| Web frontend logic | PASS, AUTO preview/cancel/save и capability gating |
| ESP32 hardware / UI core | 8 из 8 / 27 из 27 PASS |
| Реальная LVGL проверка текста 320×240 | PASS, 14 тем, EN/RU, сервисные значения и Wi-Fi |

| AUTO local/manual/reverse cycle | PASS |

и сбой persistence сохранены в поставке отдельно. Загрузочные бинарники,
partition table, S3 presets и lock-файлы не менялись этой задачей.

## Оставшиеся шаги по приоритету

1. LCD/тач: новые фото Wi-Fi и Service Status, прямые нажатия/углы. Критерий:
   нет обрезки/наложения текста, QR сканируется, выбранный пункт соответствует
   пальцу. Компоненты — `ui_screens`, существующая сохранённая touch map;
   риск — отличия физических шрифтов/панели от измерений bounding box.
2. R21: закрыть и осветить, сравнить AUTO в разных условиях, дать фильтру
   5–10 s. Критерий — темнота снижает, свет повышает яркость без дрожания.
   Компоненты — `cyd_ambient`, EMA/пороги `ui_model`; при необходимости пороги
   подобрать по фактическим крайним ADC. Не менять резисторы без измерений.
3. Долгая USB проверка: несколько часов с Wi-Fi on/off и AUTO, проверка reset,
   watchdog и heap. Короткий прогон не доказывает отсутствие долгих утечек.
4. CAN/автомобиль/питание: отдельно согласовать схему, GPIO, защиту, оконечную
   нагрузку и физические измерения. Эта задача не включает подключение к OBD
   или активные запросы; CAN остаётся заблокированным на CYD.
