# CYD 0.5.1: скорость переключения тем и отрисовки

Работа в `feature/hardware-cyd-esp32`, без слияния в main. Доработка
существующих `display_app.c` и `ui_screens.c`, без нового рендерера,
библиотек, шрифтов или формата конфигурации.

## Причины и изменения

- Локальная смена темы применяла оформление в обработчике нажатия и повторно
  при обработке сохранённой ревизии. На CYD оформление теперь применяется
  один раз при синхронизации конфигурации. Последовательные изменения,
  ожидающие обработки, объединяются; выбранная тема сохраняется как прежде.
- Настройки обрабатывали все 25 строк, включая скрытые страницы. Подбор
  шрифта каждой надписи принудительно запускал общий layout; назначение
  того же шрифта снова помечало layout/область для обновления. Теперь
  обновляются только четыре видимых пункта, геометрия разрешается на уровне
  сцены, а совпадающий шрифт повторно не назначается.
- На CYD создаются только LVGL-объекты четырёх строк текущей страницы
  настроек (одной на последней). Предыдущая страница освобождается перед
  созданием следующей, переключатель Wi-Fi живёт вместе со своей строкой.
  Освобождены объекты 21–24 скрытых строк; S3 сохраняет все свои строки.
- Пакетная смена локальных стилей выполняется под существующим LVGL mutex
  с одним последующим обновлением дерева. Пересоздание объектов для смены
  только темы не требуется. Экран по-прежнему единственный в SRAM.
- Убраны повторные записи статических заголовков/подписей, центрирование
  неизменённых кнопок и повторная установка шрифтов значений. Финальная
  подпись/заголовок выбирается перед подбором размера.
- На CYD отсутствуют программное размытие теней и полноэкранный CRT overlay.
  Яркие рамки, палитры, формы и шрифты сохраняют характер тем. Эффекты
  переходов CYD остаются отключены, как в принятой версии 0.3.1. S3 сохраняет
  свои свечения, полосы и переходы.
- Вместо одного DMA буфера 320×16 используются два 320×8 RGB565: суммарно
  те же 10 240 байт пиксельных данных. CPU готовит следующую полосу во время
  отправки предыдущей. SPI остаётся 20 MHz; разгон не используется.
- После ввода, меняющего конфигурацию, пропускается промежуточная отрисовка
  новых значений со старой палитрой/геометрией. Выбор пункта настроек может
  обновиться сразу, без ожидания очередных 200 ms обновления модели.
- Большой набор сигналов LVGL-самотеста CYD выделяется временно в heap,
  освобождается в конце и не занимает стек консоли. Для `ui_screens.c`
  добавлены измерения стека и предел локального кадра 4096 байт; фактический
  кадр самотеста после изменения — 2800 байт. Стек приложения не увеличен.

## Темы и совместимость

Все 17 идентификаторов 0–16 сохранены, включая импорт/экспорт и существующие
пользовательские настройки. Это небольшие таблицы палитр/параметров во flash,
а не 17 одновременно загруженных экранов. Удаление похожих палитр не устраняет
дорогие перерисовки; упрощены именно затраты при работе. Новых тем не добавлено.
На CYD нет теней и CRT-полос ни у одной темы; Desktop 98, Neon Arcade,
Techno 2000 и три Pixel темы остаются различимыми.

В галерее Web Configurator теперь отдельные карточки всех трёх пиксельных
тем: «Пиксели: Аркада», «Пиксели: Подземелье», «Пиксели: Портативная».
Ранее в галерее была только Аркада, остальные две находились в общем
выпадающем списке. Открытие карточки использует существующий предпросмотр,
сохранение и сброс. Галерея содержит шесть карточек; общий список — все 17 тем.

Schema 4, wire settings, NVS, калибровка, AUTO/GPIO34 и сохранённый DEMO
не мигрируются. S3 использует прежние два буфера по 16 строк. CAN остаётся
LISTEN_ONLY при DEMO OFF; разрешение TX/UDS в этой задаче не выдавалось.
Wi-Fi включается исключительно вручную из Settings.

## Проверки

Фактические результаты и численные измерения находятся в
[машинном отчёте](minidash-cyd-performance-verification-2026-10-22.json).
Код измерений публикует `MINIDASH_CYD_THEME_APPLY` (изменение стилей) и
`MINIDASH_CYD_THEME_READY` (до LVGL RENDER_READY), `status` показывает частоту
и среднее время отрисовки. Это программные события на настоящем ESP32,
не оптическое измерение LCD и не оценка плавности глазами.

Стенд: Windows, ESP-IDF 5.5.5/GCC 14.2, ESP32-D0WD-V3 rev3.1, 4 MB,
без PSRAM, CYD на COM4. Отдельные build-каталоги для CYD и ESP32-S3.
Native проверки: `cmake --build core/build-cyd-check -j4`, затем
`ctest --test-dir core/build-cyd-check --output-on-failure`. Браузерные
проверки запускают настоящий `webui.html` в Chrome с fixture HTTP peer и
native C validator; они не подменяют тесты AP на плате.

## Обновление и восстановление

Пакет `MiniDash-CYD-Performance-2026-10-22.zip` содержит приложение,
манифест SHA-256, `Update-CYD.ps1`, исходный diff и отчёты. Обновлятор
проверяет ранее сохранённый полный дамп NerdMiner, identity подключённого
чипа и хеш нового приложения. Записывается только app по 0x10000 с
последующей `verify-flash`. NVS, bootloader и partition table не стираются.

Из распакованного пакета, при исходном backup в `outputs/nerdminer-backup`:

```powershell
./firmware/Update-CYD.ps1 -Port COM4 -BackupDirectory ../nerdminer-backup
```

Для отката используется приложение CYD 0.5.0 из предыдущего проверенного
пакета: оно понимает ту же конфигурацию. Полное восстановление NerdMiner
описано в [профиле платы](minidash-cyd.md). Оригинальный дамп и частный
backup NVS не включаются в Git или общедоступный архив.

## Оставшиеся проверки

1. Физическая оценка LCD и быстрых касаний на этой версии: читаемость всех
   используемых экранов, отсутствие tearing/полос/неверной ориентации,
   ощущение отклика при смене тем. Требуется наблюдение настоящей панели;
   UART измерения этого не доказывают. При необходимости тюнинг DMA размеров
   выполняется в `display_app.c`, сохраняя RAM budget и проверяя HTTP.
2. Продолжительный прогон с живыми данными, разными пользовательскими
   страницами, автояркостью и эпизодами Wi-Fi. Критерий — отсутствие сбросов,
   монотонного падения свободной памяти и потерь touch, достаточный запас
   памяти HTTP. Короткий стендовый прогон не является суточным soak test.
3. Подключение питания/трансивера и испытание автомобиля остаются отдельным
   этапом по [инструкции CAN](minidash-cyd-can-mode-2026-10-20.md). Для
   разрешения запросов сначала нужны проверенные физические соединения.

Оформление оригинальное; новые ресурсы и сторонние зависимости не добавлены.
Лицензии существующих LVGL/шрифтов остаются прежними.

поэтому коэффициент ускорения полного кадра не заявляется. Сам RENDER_READY
не является оптическим измерением последнего пикселя панели.

В этом прогоне не наблюдались глазами LCD/физические касания/телефон,
не проверялись S3 на реальном устройстве и автомобиль. Интермиттирующая
длительная остановка из описания пользователя отдельно визуально не
воспроизводилась; приведены программные измерения на плате и устранённые
дорогие операции. Оценка плавности глазами и длительный soak остаются
задачами из списка выше.
