# Ручная прошивка VAG MiniDash на Windows

Эта инструкция предназначена для нашей ESP32-S3 N16R8: ST7789 320x240,
XPT2046, подсветка GPIO4, CAN SN65HVD230 TX=GPIO15 / RX=GPIO5.
Используется ESP-IDF **5.5.5** и режим CAN **listen-only**. Не применяйте этот
набор пинов к другой плате без проверки разводки.

Это обновление уже настроенного MiniDash с проверенной таблицей разделов
NVS 0x9000 / PHY 0xf000 / factory 0x10000. Для пустой flash или устройства с
другой таблицей сначала требуется отдельная проверка и подготовка разделов;
две команды обновления ниже сами таблицу не создают.

## 1. Подготовить устройство

1. Оставьте **CANH и CANL отключёнными от автомобиля**.
2. Подключите плату к компьютеру исправным USB-кабелем с передачей данных.
3. В Диспетчере устройств Windows откройте «Порты (COM и LPT)».
   На проверенной плате `USB-Enhanced-SERIAL CH343` имеет номер **COM3**.
   Если у вас другой номер, замените COM3 во всех командах ниже.
4. Закройте другие serial-мониторы, Arduino Serial Monitor, PuTTY и программы,
   которые могут занимать этот COM-порт.
5. Полную резервную копию не удаляйте:
   `C:\Users\user\minidash-backup\flash-before-can.bin`.

Полная резервная копия занимает 16777216 байт. Проверенный SHA256:

```text
5B7803BCE8E6E34A01EC7701CC6444B6BBA1D7344C04A044441F92F7EDA5A66B
```

## 2. Открыть правильную рабочую копию

На нашем компьютере используйте отдельный worktree:

```powershell
Set-Location 'C:\Users\user\minidash-standalone'
git status --short --branch
git log -1 --oneline
```

Единственная рабочая ветка — **`integration/standalone`**. Она объединяет
конфигуратор, русский интерфейс, режим проверки автомобиля и экранные исправления.
`feature/engine-analytics` и `fix/can-display-startup` сохранены как исторические
источники исправлений. Проверяйте `git branch --show-current`: в этой рабочей
копии результат должен быть `integration/standalone`. Подробнее —
[интеграция от 14 октября](../development/standalone-realignment-2026-10-14.md).
Если есть незакоммиченные изменения, сначала сохраните свою работу: не
сбрасывайте их и не выполняйте `reset --hard`. Не используйте исходную копию
`C:\Users\user\vag-minidash` с незакоммиченными изменениями.

Обновление чистой рабочей копии:

```powershell
git pull --ff-only
git log -1 --oneline
```

Если `pull --ff-only` отказался выполнить обновление, остановитесь и разберите
причину. Не заменяйте его force/reset-командами. Не возвращайтесь к старому
detached-коммиту `751d2f8`: в нём нет исправления переполнения стека UI.

Для нового компьютера, на котором этой рабочей копии нет:

```powershell
git clone --branch integration/standalone https://github.com/develobster/vag-minidash.git C:\Users\user\vag-minidash-manual
Set-Location 'C:\Users\user\vag-minidash-manual'
```

Далее вместо пути `minidash-standalone` используйте путь этой новой копии.
Путь установки ESP-IDF тоже может отличаться.

## 3. Включить окружение ESP-IDF

В PowerShell выполните:

```powershell
. 'C:\Espressif\frameworks\esp-idf-v5.5.5\v5.5.5\esp-idf\export.ps1'
idf.py --version
Set-Location 'C:\Users\user\minidash-standalone\firmware'
```

Ожидаем версию 5.5.5 и отсутствие ошибок проверки зависимостей. Если ESP-IDF
установлен в другом месте, укажите его настоящий `export.ps1`. Можно также
открыть установленный ESP-IDF PowerShell и перейти в каталог `firmware`.
После закрытия терминала окружение нужно включить заново.

## 4. Собрать прошивку с нужными параметрами

Скопируйте команду целиком, включая кавычки вокруг списка defaults:

```powershell
idf.py -B build-can-diagnostic -D SDKCONFIG=sdkconfig.can-diagnostic.generated -D 'SDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.listen-only;sdkconfig.uart-console' build
```

Успех — сообщение `Project build complete` без `FAILED` и ошибок компиляции.
Каталог `build-can-diagnostic` и файл `sdkconfig.can-diagnostic.generated`
отдельные: основной `sdkconfig` остаётся на месте.

Почему это важно: defaults задают исходные значения, но не обязательно
заменяют значения в уже созданном sdkconfig. Не смешивайте обычную, standalone
и диагностическую сборки в одном каталоге.

Проверить важные параметры:

```powershell
Select-String -Path sdkconfig.can-diagnostic.generated -Pattern 'MINIDASH_CAN_|MINIDASH_STANDARD_OBD|MINIDASH_DISPLAY_ENABLE|LCD_PIN_BL|ESP_CONSOLE_UART_DEFAULT'
```

Должны быть CAN_ENABLE=y, TX=15, RX=5, DISPLAY_ENABLE=y, BL=4,
UART_DEFAULT=y и `# CONFIG_MINIDASH_STANDARD_OBD is not set`.

Проверить защиту от прежней ошибки стека:

```powershell
python ..\tools\check_ui_stack_regression.py --build-dir build-can-diagnostic
```

Ожидаем `fixed_compilation: PASS` и
`broken_compilation: REJECTED_AS_EXPECTED`. Это означает, что исправленная
версия компилируется, а реальный прежний код отвергается ограничением стека.
Проверка не открывает COM-порт и не прошивает устройство. Ограничение включено
также в обычную сборку; отдельный скрипт только проверяет его работу.

Обычная сборка также автоматически проверяет вложенные пути UI/диагностики
и загрузки конфигурации с запасом 1024 байта. Ошибка этой проверки останавливает
сборку до записи устройства.

## 5. Прошить bootloader и приложение

Для первой прошивки этим профилем, перехода между USB-консолью и UART либо
неизвестного состояния bootloader выполните **обе** команды:

```powershell
idf.py -B build-can-diagnostic -D SDKCONFIG=sdkconfig.can-diagnostic.generated -p COM3 bootloader-flash
idf.py -B build-can-diagnostic -D SDKCONFIG=sdkconfig.can-diagnostic.generated -p COM3 app-flash
```

После каждой должно появиться `Hash of data verified` и `Done`.
Не отключайте USB во время записи. При отсутствии этих сообщений не считайте
операцию успешной.

Эти команды записывают bootloader по 0x0 и приложение по 0x10000. NVS по
0x9000, PHY по 0xf000 и таблица разделов по 0x8000 находятся вне записываемых
областей. Проверенная таблица: NVS 24 KiB, PHY 4 KiB, factory 3 MiB.
`erase-flash`, очистка NVS и `fullclean` не требуются.

**Почему нужен bootloader:** прежний USB-профиль отключал UART-пины при старте.
После записи только UART-приложения UI уже работал, но COM3 оставался немым.
Согласованный UART-bootloader восстановил полный лог и команды COM3.

Для последующих обновлений приложения, когда bootloader уже прошит этим же
UART-профилем и настройки запуска не менялись, достаточно `app-flash`.
Не используйте общий `flash` с чужой/непроверенной таблицей разделов.

## 6. Открыть монитор и проверить запуск

```powershell
idf.py -B build-can-diagnostic -D SDKCONFIG=sdkconfig.can-diagnostic.generated -p COM3 monitor
```

Ожидаемые признаки успешного запуска:

- PSRAM найдена, `SPI SRAM memory test OK`.
- `App version` соответствует собранному коммиту.
- `Display initialized with ST7789 backend at 320x240`.
- `STARTUP end` и `UI ready`.
- `Touch input ready; calibrated edge controls active`.
- На дисплее есть изображение и работает тач.

`MINIDASH_READY` выводится раньше готовности UI: одного этого сообщения мало.
Наблюдайте минимум 60 секунд. Новые ROM/boot-заголовки без команды reboot,
`Guru Meditation`, stack overflow и `Backtrace` означают проблему.

В мониторе введите по одной строке, нажимая Enter:

```text
status
backlight-status
```

Повторите `status` через минуту: boot-счётчик должен остаться тем же.
`backlight-status` показывает GPIO4, 5000 Гц и текущий PWM duty. Например,
для сохранённых 70% duty равен 2007/4095. Не выставляйте 70% специально,
если у вас сохранена другая яркость.

Выход из монитора: **Ctrl+]**. После этого порт освобождается для новой
прошивки. При необходимости проверьте холодный запуск отключением и повторным
подключением USB; это не стирает сохранённые настройки.

## 7. Если что-то не получилось

| Проблема | Действие |
|---|---|
| `Access denied`, порт занят | Закрыть другие мониторы, выйти из текущего через Ctrl+], проверить COM в Диспетчере устройств. |
| `Failed to connect` | Проверить USB-кабель и питание. На плате с BOOT/RESET: удержать BOOT, кратко нажать RESET, отпустить BOOT и повторить запись. |
| COM3 показывает только ROM | Проверить UART-профиль и прошить согласованный bootloader командой `bootloader-flash`. |
| Ошибка `stack usage` при сборке | Защита обнаружила слишком большой локальный кадр. Исправить код; не отключать защиту ради прошивки. |
| Экран чёрный или плата перезагружается | Сохранить полный лог от старта до первой ошибки и следующего запуска; проверить строки подсветки/UI/PSRAM. NVS не стирать. |
| Загрузка приложения успешна, тач не работает | Проверить сообщение Touch input ready и сохранённую калибровку; не сбрасывать её без диагностики. |

Лог можно записать средствами IDF Monitor: **Ctrl+T, затем Ctrl+L** включает
запись; повторное сочетание выключает её. Монитор сообщает имя файла.
Не вводите это сочетание как текстовую команду устройству.

## 8. Откат при необходимости

Полную резервную копию не прошивайте автоматически: это перепишет и NVS.
Пошаговый [откат только приложения из backup](can-display-startup-2026-10-13.md#recovery-preserving-nvs)
сохраняет текущую NVS. Старая версия приложения использует USB Serial/JTAG;
для полного возврата маршрутизации консоли может понадобиться также старый
bootloader из backup. Такой откат следует выполнять отдельно после проверки
образов и адресов, а не добавлять в обычную процедуру обновления.
