# Автономная OBD-телеметрия — 17 октября 2026

## Причина пустых приборов

На установленном образе `875106b` пользователь показал на экране статуса:
CAN RX 353855, CAN TX 0, таймауты 0, потери приёма 60, ЭБУ 0 / 000,
транспорт LISTEN. Это физическое подтверждение приёма CAN в автомобиле,
но не проверки передачи или электрической защиты питания.
USB-лог подтвердил ESP32-S3, ESP-IDF 5.5.5, ST7789 и работающий тач.

Причина отсутствия значений — сочетание отключённого STANDARD_OBD и
`profile=NULL`: приложение получает кадры, но не запрашивает стандартные
параметры и не имеет проверенного пассивного VAG-декодера.
Счётчик 92 / 92 показывал опубликованные UI-слоты, включая недоступные
значения, и не доказывал наличие 92 действительных измерений.

## Изменения

- Добавлен `firmware/sdkconfig.obd-live`: CAN 500 кбит/с, TX GPIO15,
  RX GPIO5, стандартный OBD включён, режим Car Validation отключён.
  Таким образом, действуют обычный планировщик и поддерживаемые параметры,
  а не ограниченный набор режима проверки автомобиля.
- Профиль производителя остаётся NULL: активные UDS-запросы не выполняются.
  Существующий стандартный путь использует чтение Mode 01, идентификацию
  VIN Mode 09 и чтение сохранённых DTC Mode 03 только по действию пользователя.
  Команды записи, очистки ошибок, сессий, Security Access и Routine Control
  не добавлены. Транспортный ISO-TP Flow Control для собственного ответа
  остаётся частью протокола чтения.
- Диагностика показывает «ДОСТУПНО»: valid_count / MD_SIGNAL_COUNT вместо
  количества опубликованных слотов. Это количество актуальных значений,
  включая доступные производные показатели, а не число ответов CAN.
- В стартовый лог добавлены CAN-пины, включение стандартного OBD и отсутствие
  VAG-профиля / активного UDS.

Поддерживаемые стандартные параметры: RPM, скорость, температура ОЖ,
нагрузка, абсолютное давление впуска, атмосферное давление, напряжение ЭБУ,
температура масла, IAT, наружная температура, STFT и LTFT банка 1.
Каждый параметр опрашивается только при объявленной ECU поддержке PID.
Часть параметров конкретный ECU может не предоставлять. DSG, индивидуальные
углы коррекции зажигания и другие специфичные VAG-поля требуют отдельного
проверенного источника; нельзя подставлять CAN-байты или неподтверждённые DID.
Имеющаяся производная аналитика использует только доступные исходные значения.

Планировщик сохраняет общий интервал запросов не меньше 100 мс,
ограничение повторов и одиночную аппаратную отправку без бесконечных ретраев.
Первоначальное прослушивание перед передачей сохраняется.

## Сборка и совместимость

Сборка `obd-live-20261017`: ESP-IDF 5.5.5, закреплённые локальные компоненты,
`IDF_COMPONENT_MANAGER=0`, `IDF_CCACHE_ENABLE=0`, шесть задач сборки.
Исходная аппаратная конфигурация скопирована из принятого USB-образа;
сохранены дисплейные GPIO, UART0 + USB Serial/JTAG, PSRAM, Flash 16 МБ и
таблица разделов. Схема настроек не меняется.

```powershell
. 'C:\Espressif\frameworks\esp-idf-v5.5.5\v5.5.5\esp-idf\export.ps1'
$root = 'C:\Users\user\minidash-standalone'
Set-Location $root
$env:IDF_COMPONENT_MANAGER = '0'
$env:IDF_CCACHE_ENABLE = '0'
$env:IDF_PY_BUILD_JOBS = '6'
idf.py -C firmware -B "$root/.local/firmware-builds/obd-live-uart" `
  "-DSDKCONFIG=$root/.local/sdkconfig-obd-live-uart.generated" `
  '-DSDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.obd-live;sdkconfig.uart-console' `
  "-DEXTRA_COMPONENT_DIRS=$root/.local/pinned-components" `
  -DCCACHE_ENABLE=0 -DPROJECT_VER=obd-live-20261017 build
```

Для новой независимой сборки SDKCONFIG должен быть новым файлом. Существующий
SDKCONFIG имеет приоритет перед defaults: нельзя ожидать переключения режима
при простой смене SDKCONFIG_DEFAULTS у прежнего пассивного конфига.

## Проверка и запись

На момент подготовки отчёта восемь существующих CTest-проверок ядра прошли:
приём/опрос, аналитика и интеграция с ней, UI, конфигурация, профили,
подсветка, режим Car Validation. Они используют синтетические данные,
а не подтверждают поддержку PID конкретным Tiguan.

Сборка ESP-IDF завершилась без предупреждений и ошибок; приложение занимает
1 856 816 байт (`0x1c5530`), в разделе остаётся 41% свободного места.
SHA-256 образа: `d08ab34d197cf2b239f9a1975be587de666b9c1498c42f8ecfd43b5573ebe4ce`.
JSON-конфигурация нового загрузчика побайтно по значениям совпала с конфигурацией
принятой сборки; обновлять установленный загрузчик не требуется.
Дополнительный Python VirtualBus launcher остановился до запуска из-за отсутствия
`python-can` в системном Python; восемь CTest-проверок выше выполнены отдельно.

Пользователь подтвердил: устройство отключено от OBD и подключено к ПК только
по USB. Через COM5 / USB Serial-JTAG успешно выполнена запись приложения
`obd-live-20261017` по адресу 0x10000. Esptool 4.12.0 проверил hash при записи;
отдельный `verify_flash` подтвердил совпадение digest с образом.

Перед записью сохранены свежие 3 211 264 байта диапазона 0x0..0x30ffff и
отдельный предыдущий раздел приложения для отката. SHA-256 свежей копии:
`a3c82b22dee17bb156cf638dcaec50ffeaff2001742b0ce132f633f43b5fd840`.
Проверены таблица разделов и принятый UART-загрузчик: его 22 272 байта имеют
SHA-256 `c0ee5dbb9f34f973270e943889095304908f25b65d0e7ff6d17f9b67ab5ac95c`.
Secure Boot и Flash Encryption на устройстве отключены. Первые 64 КиБ до/после
записи побайтно совпали: NVS, калибровка, PHY, таблица разделов и загрузчик
сохранены. Полное стирание не выполнялось.

После управляемого сброса по USB получен лог:

## Использование и восстановление

OBD pin 16 соединён со входом LM2596. Для автомобиля использовать только
OBD-питание, без USB. Для прошивки/USB-лога сначала полностью отключить OBD,
затем подключить USB. Защита от обратной подачи питания и автомобильных
импульсов этой работой не подтверждена. Автономной работе компьютер не нужен.

После успешной USB-записи: отключить USB, подключить OBD при выключенном
зажигании, включить зажигание и запустить двигатель на стоянке; проверить
RPM и температуру ОЖ. Если ECU не ответил, посмотреть транспорт, число ECU,
TX и таймауты: подтверждённый RX ещё не доказывает исправность TX цепи.
Во время обычного измерения не удерживать диагностический экран.

Для отката использовать сохранённый файл `before-obd-live-<timestamp>-app.bin`
и запись только по адресу 0x10000 при USB-only подключении. Файл содержит
предыдущий раздел приложения; свежая общая копия также содержит настройки,
загрузчик и таблицу разделов. Исторические копии не перезаписывать.

Приоритет дальнейшей работы: подтвердить живые стандартные параметры на
конкретном автомобиле; затем составить список недоступных требуемых полей
и подобрать для них доказанный источник. Для VAG-профиля нужны сведения об
ECU и лицензированные/проверенные определения. Активные UDS-запросы остаются
вне разрешённого объёма этой задачи.
