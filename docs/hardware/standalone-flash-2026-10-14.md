# Стендовая загрузка единой версии MiniDash — 2026-10-14

На ESP32-S3 установлено приложение **`875106b`** из чистого коммита
`875106bf1cdd6ae477941d0115911d33b8509751`, ветка **`integration/standalone`**.
Объединённая версия запустилась, 27 проверок UI прошли. Пользователь подтвердил:
**«Да, изображение и тач работают»**. Русский язык, настройки и калибровка
сохранены. Это новая физическая проверка после
[объединения веток](../development/standalone-realignment-2026-10-14.md).

Прошивка выполнялась на столе через **COM3**, питание только от USB.
Перед записью пользователь подтвердил: **«Да, только USB; CANH/CANL отключены»**.
Применён постоянно пассивный профиль Car Validation с UART-консолью.
Автомобиль и физический приём CAN в этой задаче не проверялись.

## Что изменилось и совместимость

На плате прежнее приложение `da1e6b7` заменено объединённым `875106b`.
Исходный код, зависимости, форматы API и таблица разделов в этой задаче
не изменялись. Сохранены русский интерфейс, автономная аналитика, локальные
настройки и режим проверки автомобиля из интеграционной ветки. Схема
сохранённых настроек осталась **4 → 4**, миграция не понадобилась.
Язык в экспорте — `1` (русский), яркость — 70%, пользовательский поворот — 0.
Полные разделы `common` и `platform` совпали до/после обновления и после
командной перезагрузки; действующая калибровка XPT2046 загрузилась.

В репозитории добавлены этот отчёт и
[машинная сводка](standalone-flash-verification-2026-10-14.json), обновлены
указатели README, текущего состояния, дисплейного прототипа, ручной инструкции
и отчёта интеграции. Коммит документации следует после `875106b` и не меняет
версию уже записанного приложения.

  "-DSDKCONFIG=$PWD/.local/sdkconfig-validation-listen-uart.generated" `

183 192 байта, остаток DIRAM по компоновщику — 62 917 байт. Это расчёт

## Почему записано только приложение

Таблица разделов на устройстве точно совпала с новой сборкой, включая все
4096 байт по адресу `0x8000`. NVS занимает `0x9000..0xefff`, PHY —
`0xf000..0xffff`, factory-приложение начинается с `0x10000`, размер — `0x300000`.

На плате уже находился согласованный UART-загрузчик, принятый ранее.
Все его 22 272 байта совпали с сохранённым принятым образом из существующей
сборки `vag-minidash-can/firmware/build-can-diagnostic/bootloader/bootloader.bin`.
Его SHA-256:
`c0ee5dbb9f34f973270e943889095304908f25b65d0e7ff6d17f9b67ab5ac95c`.
Полные JSON-конфигурации старой и новой сборок bootloader также совпали.
Поэтому повторная запись загрузчика не требовалась.

В этой задаче записан **только адрес `0x10000`**, скорость 921600.
`esptool write_flash` подтвердил хеш; отдельный `verify_flash` подтвердил
совпадение digest с сохранённым образом. NVS, PHY, таблица разделов и загрузчик
не записывались. Полное стирание и `fullclean` не выполнялись.

Основные операции esptool (после проверки устройства, образа и разделов):

```powershell
python -m esptool --chip esp32s3 --port COM3 --baud 921600 read_flash 0x0 0x1000000 artifacts/hardware/before-875106b-passive-uart-20261014.bin
python -m esptool --chip esp32s3 --port COM3 --baud 921600 write_flash 0x10000 artifacts/hardware/vag-minidash-875106b-passive-validation-uart.bin
python -m esptool --chip esp32s3 --port COM3 --baud 921600 verify_flash 0x10000 artifacts/hardware/vag-minidash-875106b-passive-validation-uart.bin
```

Это запись выполненных операций, а не предложение повторно перезаписать
существующую резервную копию. При следующем обновлении использовать новое имя
копии и повторно проверять разделы/консоль. При неизвестном загрузчике или смене
USB→UART сначала следовать [ручной инструкции](manual-flashing-ru.md): исторически
обновления только приложения было недостаточно для перехода между консолями.

## Оставшаяся работа и восстановление

1. **P0 — холодное включение этой версии.** Цель: проверить запуск и сохранение
   NVS после реального снятия питания. Компоненты: загрузчик, питание, UI/NVS.
   Нужен владелец с USB-стендом. Критерий: после отключения/подключения USB
   изображение и тач работают, настройки сохранены, UART не показывает цикл
   сбросов. Пока это не подтверждено; автомобиль для такой проверки не нужен.
2. **P0 — пассивный сеанс на неподвижном автомобиле.** Цель: подтвердить питание,
   трансивер и фактический RX. Нужны проверенная защищённая проводка и отдельный
   сеанс по [инструкции Car Validation](../validation/car-validation-mode.md).
   Критерии: TX=0, реальные RX/ошибки, отсутствие сбоев шины и приватные снимки.
   Риски: автомобильное питание, неверная проводка/терминация. Стендовая загрузка
   не подтверждает эти электрические условия.
3. **P1 — длительная нагрузка и источники.** Измерить минимальные остатки стеков
   и кучи при UI+CAN+Wi-Fi, устойчивость записи и перезапуски. Для фирменных
   источников нужны отдельные доказательства идентичности ЭБУ, адресов, длины,
   масштаба, TTL и эталона. До этого соответствующие привязки остаются выключены.

Для восстановления сначала сохранить текущее состояние отдельной копией,
проверить адрес factory-раздела и совместимость консоли. Возврат только
приложения из первоначального backup сохраняет текущую NVS; полная запись
16 МиБ восстановит также старые настройки. Последний снимок 64 КиБ содержит
загрузчик, таблицу, NVS и PHY вместе и не предназначен для слепой записи целиком.
Пошаговая процедура: [восстановление с сохранением NVS](can-display-startup-2026-10-13.md#recovery-preserving-nvs).
В этой задаче откат не выполнялся; исправный образ оставлен запущенным.

Использованы собственные исходники репозитория, установленный ESP-IDF,
закреплённые зависимости и прежний принятый UART-загрузчик. Новые внешние
реализации или лицензируемые базы не импортировались, лицензии не менялись.
Исторические ветки, `main` и посторонние рабочие каталоги сохранены.
