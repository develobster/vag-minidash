# MiniDash Display Studio — 20 октября 2026

Обновлён **конфигуратор, который обслуживает сама плата**: Settings → Wi-Fi →
Enable → QR / `http://192.168.4.1`. Ветка `feature/hardware-cyd-esp32`, исходная
точка `6d4cbc2`. CYD: версия `cyd-0.4.0-studio`. Слияние в main не выполнялось.
Отдельный конфигуратор ПК `minidash_live/web` использует другой формат настроек;
его приложение не заменяется устройственным редактором. Это решение продолжает
текущий сеанс работы с CYD и существующий embedded Web Configurator.

## Что изменилось и как пользоваться

Редактор разделён на «Редактор», «Оформление», «Устройство», «Сигналы и события»,
«Файлы». На широком экране — боковое меню, рабочее поле и инспектор окна;
на телефоне они идут последовательно. Нижняя панель показывает состояние
изменений, ошибки, чтение с устройства, отмену, временный показ и сохранение.

Окно можно выбрать непосредственно на рабочем поле или в списке под ним.
Перетаскивание перемещает его по сетке; нижний правый угол меняет размер.
Инспектор содержит поиск сигнала, вид окна, подпись, координаты и размер.
Точность/диапазон и выравнивание находятся в раскрываемых группах. Есть
дублирование в свободное место, добавление и удаление окна, копирование/удаление
страницы, восемь существующих шаблонов компоновки и шесть шаблонов аналитики.
Кнопка «Сделать главным» выбирает существующий Custom dashboard.

Все изменения сразу отражаются **в браузере**, без HTTP-записи на каждом
движении. «На дисплей» вызывает существующий `/api/preview`, «Сохранить» —
`PUT /api/config`, «Отменить» — `/api/cancel`. Временный вариант не становится
сохранённым автоматически. Отмена может восстановить сохранённый вариант даже
после локального ввода некорректного диапазона: в cancel передаётся валидная
сохранённая конфигурация с текущей revision. HTTP token и optimistic revision
остаются обязательными; конфликт сохраняет черновик и предлагает экспорт/чтение.
Во время сетевой операции редактируемая область inert, повторная запись закрыта.

История до 40 действий живёт в памяти вкладки. Повторный ввод в одно поле
объединяется в короткую группу. Ctrl/⌘+Z — отмена, Shift+Ctrl/⌘+Z или Ctrl/⌘+Y —
повтор, Ctrl/⌘+S — сохранение. Когда фокус на окне, стрелки двигают его,
Shift+стрелки меняют размер, Delete удаляет. Esc прерывает drag. Для сенсорного
экрана телефона используются Pointer Events; числовые поля дают альтернативу
точному попаданию в угол. Видимость сетки переключается отдельно от привязки.

Предупреждения вводятся в обычных единицах сигнала (например °C или V), затем
переводятся в прежние целочисленные `*_milli`; wire/API не меняются. У яркости
есть ползунок и числовая подпись, AUTO зависит от возможности устройства.
Производные события и сбросы на CYD недоступны и отключены явно; импортируемые
параметры сохраняются для совместимости. Поиск сигналов/шкал имеет пустое
состояние. Есть загрузка, ошибки соединения/сессии/конфликта, подтверждение
разрушительных сбросов, защита ухода с несохранёнными изменениями.

## Четыре направления оформления

| Тема | ID | Характер |
|---|---:|---|
| Пиксели: Аркада | 11, существующий | Bitmap-шрифт дисплея, ступенчатые рамки, моноширинные заголовки рабочего места |
| Рабочий стол 98 | 14, новый | Прямоугольные рельефные панели, моноширинный дисплей, заголовок инспектора с цветной полосой |
| Неоновая аркада | 15, новый | Фиолетовый CRT, бирюзовый акцент, моноширинные приборы, scanlines и сдержанное свечение |
| Техно 2000 | 16, новый | Синие хромированные поверхности, округлые панели, световой градиент и рамки |

Все прежние ID 0–13 сохранены. Новые темы добавлены в общий C-каталог,
локальный выбор на дисплее и API `/api/themes`; это не только браузерная окраска.
LVGL использует существующий renderer: дополнительные линии рельефа рисуются
перед текстом без framebuffer, холста или анимированного таймера; у Techno есть
градиент поверхности. Смена темы сохраняет страницы и их расположение.
Своя палитра, контрастная подсказка, возврат палитры текущей темы и выбор OEM
работают через прежние `theme/custom_theme/palette`. Ресурсы игр, логотипы,
внешние шрифты, CDN и новые runtime-зависимости не используются. Код и палитры
оригинальные, лицензия проекта MIT; прежние лицензии шрифтов остаются в силе.

## Модель, ограничения и совместимость

`firmware/main/webui.html` остаётся самостоятельным HTML/CSS/JS ресурсом,
встроенным ESP-IDF в flash. Исходник отформатирован для сопровождения; размер
HTML около 98 KiB, новых сетевых ресурсов нет. Запросы каталогов при загрузке
последовательны: на CYD не создаются одновременно несколько JSON-деревьев.
Для статического HTML снята блокировка LVGL на время сетевой отправки; JSON
сохраняет прежнюю защиту от одновременных тяжёлых аллокаций.

Сетка — те же 12×8, до 4 страниц и 8 окон, минимум окна 3×2. Portrait обратимо
транспонирует координаты, а хранит прежние клетки. Первый ручной сдвиг/размер
выбирает существующий `layout=0`. Перекрытия и выход за край не записываются;
неудачное выравнивание сохраняет прежнее положение. Если дубликат не помещается,
показывается объяснение, окно не создаётся. Управления слоями нет: эта модель
запрещает перекрывающиеся окна, поэтому фиктивный z-index не добавлялся.

Schema 4, codec/NVS, размер структур, сигналы, платформенные настройки и API
записи сохранены. Импорт версий 1/2/3 мигрирует по прежним правилам, затем
проверяет геометрию, сигналы, диапазоны и UTF-8 длины перед заменой черновика.
Неизвестная версия и неверный файл не заменяют рабочую конфигурацию.
Сервер остаётся окончательным валидатором. Значения вне диапазона и обязательные
пустые числовые поля блокируют сохранение. Калибровка touch и пароль AP не
попадают в UI-экспорт, изменения не стирают NVS.

Предпросмотр — **схема**, не точная копия LVGL и не поток телеметрии: он показывает
сигнал, тип, геометрию и оформление без выдуманных измерений. Шрифты браузера,
точные метрики, DAY-палитры старых светлых тем и физическая яркость могут отличаться
от LCD; точный вид проверяется кнопкой «На дисплей». Пиксельные переходы CYD
по-прежнему отключены. Автоматическое включение Wi-Fi и CAN/UDS не добавлялись.


На Windows executable имеет `.exe`; задать эти пути аргументами. Для браузера

Это fixture-сервер на loopback со случайным портом, без USB/CAN и с закрытием
процесса браузера после теста. `--validate` в native JSON executable читает
JSON из stdin и проверяет его теми же parser/validator, что прошивка.

## Обновление и оставшаяся приёмка

В поставке CYD app-only `minidash-cyd-app.bin` для `0x10000`, контрольные суммы,
скрипт проверки исходного NerdMiner backup/идентичности платы и приложение
0.3.1 для отката. Не стирать всю flash и NVS для обновления MiniDash.
Перед откатом выбрать и сохранить тему ID 0–13: старый образ не знает 14–16.
Полное восстановление NerdMiner выполняется прежним verified 4 MiB dump на
`0x0`, не приложением MiniDash. Backup содержит приватные данные и не в Git.

1. При подключении CYD проверить app-only загрузку, обычный boot с Wi-Fi OFF,
   AUTO/калибровку/страницы после reboot и ручной AP → новый редактор. Критерий:
   прежние настройки сохранены; изменения Save/Cancel видны на LCD. Нужны USB
   и телефон, риск — особенности captive browser и новая нагрузка каталога тем.
2. Проверить на LCD новые три темы, EN/RU, обе ориентации, маленькие окна,
   длительный прогон памяти с AP. Сборка/Chromium не подтверждают качество
   физической отрисовки или запас heap. Необходимы UART и наблюдение панели.
3. Полноценный телеметрический browser preview и более свободный дизайнер
   требуют новых API/модели и отдельного бюджета RAM. Критерий будущего шага:
   реальные quality states и отсутствие конкуренции с диагностическими задачами.
   Текущая задача не выдаёт пустые значения за live telemetry.
4. CAN и защищённое питание продолжают отдельный аппаратный этап по CYD guide:
   подтверждённые GPIO/модуль/терминация/питание и стенд, затем разрешённые
   проверки автомобиля. Эта задача не меняет прежнюю блокировку передачи.
