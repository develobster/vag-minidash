# MiniDash: ревью, консолидация и аппаратная документация

Срез: **5 ноября 2026, Europe/Minsk**. Репозиторий: `develobster/vag-minidash`.
Проверяемый код: `63e3c543dc07d8034b4443e9d20050463fed11dc`.
До консолидации основная ветка: `c10b76b568163ff7e983c858bdf5c1a32be89bb7`.

## 1. Главный результат

Проект имеет работающую программную базу для двух цветных устройств: ESP32-S3
с отдельным TFT/XPT2046 и CYD ESP32-2432S028R. Обе используют общее C-ядро,
LVGL, конфигурацию и сбор данных. Для CYD есть более свежая USB-приёмка интерфейса.
**Ни одна сборка пока не принята как достоверный автомобильный прибор на Tiguan.**
Воспроизведение, DEMO и зелёный CI не закрывают эту границу.

Проверка графа всех 17 remote branches показала: каждый их HEAD является предком
`integration/cyd-unified` либо совпадает с ним. Несобранных уникальных коммитов
в старых ветках нет. `integration/standalone` отстаёт на 26 коммитов и допускает
fast-forward. Консолидация выполнена в рабочей копии без конфликтов и изменения
кода относительно проверенного `63e3c54`; документация и механические макеты
добавляются отдельным коммитом. Единственная база продолжения -
`integration/standalone`. Старые ветки сохраняются; `main` не изменяется.

Пакет содержит проверяемую карту веток, текущую матрицу функций, электрические
соединения по именам контактов, порядок пайки/проверки и параметрические макеты
корпусов. Внешний вид реального разъёма и порядок его контактов не выдумываются.

## 2. Что именно проверено

- Полный git clone с remote refs; ancestry и число уникальных коммитов для каждой
  ветки; diff двух интеграционных веток: 93 файла, +10408/-383 строк.
- Исходники приёма CAN, SPSC-очереди, тройного снимка UI, смены источника CYD,
  backoff, ограничителя запросов, таймера Drag, power/Wi-Fi policy и конфигураций.
- Текущие build presets, component locks, CI matrix, генераторы сигналов,
  аппаратная документация и исторические записи USB/автомобильных испытаний.
- Локальные тесты на Linux/GCC; отдельная проверка замкнутости STL. Плата,
  автомобиль, USB/COM и измерительные приборы в этой сессии не подключались.

Это ревью архитектуры, интеграции и готовности продукта. Оно не является
формальным доказательством отсутствия ошибок во всех строках или электрической
аттестацией устройства. Приватные дампы, VIN и резервные копии не публикуются.

Порядок консолидации и восстановления:

1. Получить refs и убедиться в чистом worktree; сохранить чужие изменения.
2. Проверить `git merge-base --is-ancestor` и `git rev-list --left-right --count`.
3. На `integration/standalone` выполнить `git merge --ff-only origin/integration/cyd-unified`.
4. Прогнать host/build matrix, добавить документацию и отправить обычным push.
5. Сверить удалённый SHA; не удалять исторические refs и не делать force-push.

Все завершённые функции уже в общей истории; повторно cherry-pick старых
feature-веток делать не нужно. `integration/cyd-unified` теперь историческая
точка интеграции, а не вторая независимая линия разработки.
При необходимости расследования использовать отдельный detached worktree на
`c10b76b` или `63e3c54`; общую ветку назад не переписывать. Откат устройства -
только проверенный бинарник и совместимая таблица разделов, с сохранением NVS.

## 5. Находки ревью и риски

**R1 / P0: автомобильная телеметрия не принята.** В октябрьской S3-проверке CAN
принимался, но ответы ECU/живые показатели не были получены. Стендовый loopback
20/20 для canfix19 проверяет часть пути, не шлюз Tiguan. У CYD последний CAN
readiness review проходил на USB без автомобиля. Нужны лог, точка подключения,
режим, GPIO, RX/TX/error/drop counters и параллельные контрольные показания.

**R2 / P0: электрическая схема питания остаётся прототипной.** LM2596S и
предохранитель не доказывают стойкость к автомобильным импульсам. Не подтверждены
защита переполюсовки, скоординированный TVS, backfeed USB и рабочий ток. TVS не
считать установленным по списку покупок. До постоянной установки нужен отдельный
защищённый power design и его измерения. OBD16 обычно постоянно запитан.

**R3 / P1: CYD имеет тесный бюджет SRAM.** В историческом USB-тесте после AP
свободная память была около 79.8 KB, минимум около 28.7 KB, largest block 32 KB;
это выборочные старые наблюдения, не гарантированный запас. Исправлены single-scene
UI и потоковая сериализация JSON. Необходим длительный CAN+HTTP+touch soak test,
стековые high-water marks, largest block и отсутствие тренда утечки.

**R4 / P1: достоверность замеров Drag пока программная.** `drag_timer.c` требует
trusted speed, устойчивую остановку, отбрасывает выбросы, gaps >1 с и смену
passive/active source. Время интерполируется по CAN/OBD-выборкам. Ограничение
5 запросов/с относится ко всем PID, а не к скорости отдельно: экран не даёт
сертифицированной точности 0-100 без реальной оценки интервалов и задержек.

**R5 / P1: рассогласованный статус документации.** `HARDWARE.md` и
`docs/architecture/targets.md` содержали старые планы OLED/no native acquisition,
а CYD-интеграция находилась вне default branch. Добавлены актуальные указатели;
исторические отчёты сохранены с их датами. Этот отчёт - текущий навигатор.

**R6 / P2: управление репозиторием.** API сообщает `protected=false` у всех
17 веток; это не полная проверка rulesets. В workflow permissions ограничены
`contents: read`, зависимости firmware закреплены версиями/locks. GitHub Actions
используют major tags, а не immutable SHA; закрепление Actions и branch rules
остаются отдельным улучшением. Настройки доступа в этой задаче не менялись.

Не выявлено нового блокера для fast-forward по пройденным тестам. Это заключение
об объединении кода, а не об автомобильном релизе. NVS-пути/часть UI продолжают
использовать блокировки; новый RX путь вынесен отдельно, поэтому весь firmware
нельзя описывать как полностью lock-free.

## 6. Аппаратные варианты и комплектующие

| Вариант | Подтверждённая база | Что добавляется снаружи |
|---|---|---|
| S3 / TFT | ESP32-S3 N16R8, 2025-V1.4; TFT 2.4″ SPI V1.3, XPT2046 | SN65HVD230, проверенный 5 В power path, жгут OBD, выключатель, корпус |
| CYD | ESP32-2432S028R / классический ESP32 4 MB; ILI9341/XPT2046 | SN65HVD230 и свой жгут/питание; встроенный TFT перепаивать не нужно |
| Lite | Bluepill имеется у владельца; назначение в продукте не утверждено | Сначала выбрать OLED/MCU/драйверы; только затем BOM и разводка |
| Host / VNCI | Исследовательский PC transport | Не третье встроенное устройство и не часть конечной S3/CYD сборки |
| Premium P4/MIPI | Историческая идея | Нет выбранной/собранной платы; схема пайки и пригодный корпус невозможны без неё |

Для каждого активного устройства требуется собственное подтверждение модуля
CAN, напряжений и жгута. Нельзя переносить проверку трансивера S3 на CYD.
Номиналы предохранителя 0.5-1 A - прежний ориентир прототипа; выбрать по
реальному рабочему/пусковому току, сечению проводов и характеристике срабатывания.
Подпись KCD11 не доказывает допустимый DC-ток конкретного экземпляра.

## 7. Питание, масса и CAN

Наглядные листы: [питание](wiring/01-power.svg), [S3 CAN](wiring/02-s3-can.svg),
[S3 дисплей](wiring/03-s3-display.svg), [CYD CAN](wiring/04-cyd-can.svg),
[Lite concept](wiring/05-lite-concept.svg). Рядом лежат PNG и `nets.csv`.

| Откуда | Куда | Условие |
|---|---|---|
| OBD16 | F1 → KCD11 → DC/DC IN+ | Плюс автомобиля; предохранитель у источника |
| OBD4 | DC/DC IN− | Возврат питания |
| DC/DC OUT+ | S3 5V или CYD проверенный 5V/VIN | Измеренные 5 В; не вход 3V3 |
| DC/DC OUT− | GND платы | У LM2596 IN−/OUT− общие, не гальваническая развязка |
| OBD5 | Опорная масса по проверенному жгуту | Исторически в удлинителе 4/5 объединены; не угадывать по цвету |
| 3V3 платы | CAN VCC | SN65HVD230 питается от 3.3 В, не от 5 В |
| GND платы | CAN GND | Общая сигнальная опора |
| OBD6 / OBD14 | CANH / CANL | Витая пара, короткое ответвление |

«Общая масса» не требует отдельного длинного провода к каждому узлу от OBD.
В существующем неразвязанном прототипе минус приходит в DC/DC, далее OUT− к
плате и от общей точки к CAN/экрану. Следить за качеством соединений и не делать
возврат силового тока через тонкий провод сигнального модуля.

Ориентироваться на подписанные номера контактов разъёма и прозвонку. Вид со
стороны проводов зеркален виду со стороны контактов; картинки этого пакета
не задают вид колодки и специально не рисуют неподтверждённое расположение пинов.
Цвета линий - легенда схемы, не утверждение о цветах готового удлинителя.

Для SN65HVD230: D=TX вход трансивера (CTX/TXD), R=RX выход (CRX/RXD),
VCC=3.3 В, GND общий. На самом чипе D=1, GND=2, VCC=3, R=4,
CANL=6, CANH=7; это номера корпуса IC, а не порядок header breakout.
RS=8: режим зависит от разводки модуля; не переделывать без проверки.
Локальная развязка питания 100 нФ должна быть у модуля/IC; проверить уже имеющуюся.
Vref не использовать как питание. Источник: TI SN65HVD23x datasheet.

На оконцованную автомобильную CAN-шину не добавлять третий 120 Ω.
У исторического S3 breakout R2 был снят; для CYD это не установлено. На отдельном
двухузловом CAN-стенде нужны окончания по обоим концам. Сопротивление измеряют
только на обесточенной безопасно отключённой цепи.

## 8. Куда паять: S3 с отдельным экраном

| Контакт ESP32-S3 | Контакт модуля | Примечание |
|---|---|---|
| GPIO15 | SN65 CTX/TXD | Текущий CAN TX во всех S3 CAN presets |
| GPIO5 | SN65 CRX/RXD | CAN RX |
| 3V3 / GND | SN65 VCC / GND | Не 5 В |
| GPIO12 | TFT SCK + T_CLK | Общий тактовый SPI |
| GPIO11 | TFT SDI/MOSI + T_DIN | Общий MOSI |
| GPIO10 | TFT CS | Только LCD chip-select |
| GPIO8 | TFT DC/RS | Данные/команды |
| GPIO9 | TFT RESET/RST | Reset LCD |
| GPIO13 | T_DO | MISO тача; TFT SDO оставлен неподключённым |
| GPIO14 | T_CS | Только touch chip-select |
| 3V3 / GND | TFT VCC / GND | Для существующего проверенного модуля |
| GPIO4 | TFT LED | Только условно для известного модуля; см. ниже |

T_IRQ не используется. GPIO4 управляет подсветкой существующего модуля;
исторически пользователь подтвердил PWM. Ток входа/схема Q1 ещё не измерены:
на другом TFT нельзя подключать LED-нагрузку напрямую к GPIO по этой инструкции.
Если LED не является совместимым управляющим входом, нужен отдельный драйвер.
Никогда не соединять LED одновременно с 3V3 и GPIO4. Схемы с TX17/RX16 не
соответствуют текущим S3 presets и должны считаться устаревшими для этой сборки.

Порядок: обесточить → проверить маркировку GPIO → припаять общую землю и питание
с изоляцией → SPI/CS → проверить на USB изображение/тач → подключить CAN-модуль
3.3 В → проверить CAN на изолированном стенде. Не перепаивать работающий TFT
ради консолидации ПО; таблица нужна для сборки/сверки, не как команда переделать плату.

## 9. Куда паять: CYD

| Контакт CYD | Контакт CAN | Статус |
|---|---|---|
| CN1 IO22 | CTX/TXD | Выбран firmware; реальную прозвонку выполнить |
| CN1 IO27 | CRX/RXD | Выбран firmware; реальную прозвонку выполнить |
| CN1 3.3V | VCC | Проверить 3.3 В мультиметром |
| CN1 GND | GND | Проверить общий минус |
| Проверенный VIN/5V | DC/DC 5 В | Проверить трассу платы; не подавать 12 В |

CN1 - подписанные GND/IO22/IO27/3.3V классической CYD; порядок по фотографии
не назначается. GPIO22 также есть на P3. P3 IO21 занят подсветкой, IO35 только
вход; GPIO35 не является автоматической заменой RX27 без изменения конфигурации.
TFT, touch, LDR уже распаяны на CYD: внешние соединения к ним не нужны.
Встроенные SPI: LCD SCLK14/MOSI13/MISO12/CS15/DC2/BL21;
touch SCLK25/MOSI32/MISO39/CS33, IRQ36 не используется.

Порядок: найти CN1 по шелкографии → прозвонить контакты → подготовить короткий
съёмный жгут 3V3/GND/TX22/RX27 → проверить отсутствие замыканий → первый запуск
только USB, без автомобиля → убедиться, что DEMO выключен, listen-only, TX unarmed
→ стендовый CAN → отдельная пассивная сессия на неподвижном автомобиле.
Не припаивать провода к ногам ESP32 при наличии доступного подписанного разъёма.

## 10. Корпуса и печать

Исходник: [minidash.scad](../../hardware/enclosures/minidash.scad),
[подробная инструкция](../../hardware/enclosures/README.md).
Для S3, CYD и концептуального Lite подготовлены compact, hood и panel.
Итого 9 компоновок, 18 STL деталей (основание + рамка) и один STL купона.
Основания внутри тройки намеренно одинаковые: меняется рамка, это совместимые варианты.

Модели замкнуты, имеют положительный объём и проверенную согласованность нормалей.
Это проверка геометрии, не посадки электроники, печатаемости без поддержек или
прочности в автомобиле. Отверстия USB/KCD11 и крепления PCB не выдуманы: добавить
их после обмера. Ввод 7 мм и окна дисплея - параметры для примерки.
Фиксация носителя предусмотрена полочками и стяжками; стекло нельзя зажимать.

На первом шаге напечатать купон и рамку. Для S3 измерить отдельно контроллер,
TFT PCB/стекло и высоту проводов; для CYD - всю плату с USB/CN1 и компонентами.
Для Lite сначала выбрать OLED и компоновку кнопок. Использовать размеры из
картинки генерации как измеренные нельзя. Художественные концепты показывают
направления дизайна, а точный вид STL приведён в `cad-s3.png`, `cad-cyd.png`,
`cad-lite.png`. Кнопки/люки на концептах могут отсутствовать в параметрическом макете.

## 11. Сборка, воспроизведение и прошивка

Из корня репозитория, в экспортированном ESP-IDF **5.5.5**:

```sh
python tools/build_firmware.py esp32_s3
python tools/build_firmware.py minidash_cyd --listen-only
```

Первая команда собирает S3 standalone, вторая - CYD с отключёнными стандартными
OBD-запросами. Для пассивного S3 использовать отдельный чистый build/config:

```sh
idf.py -C firmware -B build-s3-listen -D SDKCONFIG=sdkconfig.s3-listen.generated -D 'SDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.listen-only' build
```

Не переносить sdkconfig между esp32 и esp32s3. Если меняется путь/target,
использовать новый build directory. Согласовать bootloader/partition table/app;
app-only обновление безопасно для настроек только после проверки совместимости.
Перед прошивкой иметь локальный проверенный backup и экспорт настроек.
Номер COM/serial port определяется заново. Автомобиль и внешнее питание отключить.
В этой задаче новая прошивка на реальные платы не записывалась.

Host-проверки и воспроизведение:

```sh
python -m pip install -r requirements-transport.txt -r requirements-data.txt
python scripts/generate_can_signals.py --check
python scripts/generate_vag_can_db.py --check
python -m unittest discover -s tests -v
node --test tests/frontend/model.test.js tests/frontend/units.test.js
python -m minidash_live.configurator
python -m minidash_live --help
```

Форматы записей/CLI: [CAN replay](../runtime/can-replay.md),
[VAG/Drag implementation](../development/vag-platforms-drag-ui-2026-10-27.md).
Не считать успешную синтетику доказательством коэффициентов на автомобиле.
