# MiniDash: первый автономный тест

Версия: ветка `feature/standalone-acquisition`, точный commit записать перед
прошивкой. Это инструкция для **непроверенного на машине прототипа**, не допуск
к постоянной установке. Первый запуск — на неподвижной машине, P, стояночный
тормоз. Не управлять интерфейсом во время движения.

## 1. До подключения

- Проверить распиновку **своего** OBD-разъёма и платы мультиметром/документацией:
  OBD6 CAN-H, OBD14 CAN-L, OBD16 питание, OBD4/5 ground. Не ориентироваться только
  на цвета жил или вид разъёма на фотографии.
- Installation preset: GPIO4 ESP32 → TXD SN65HVD230, GPIO5 ← RXD; transceiver
  питается от 3.3 V, общая сигнальная земля. Проверить маркировку модуля и RS.
  Это предложенная распайка, не утверждение, что она уже собрана.
- Не подавать 12 V на ESP32/transceiver. Питание прототипа: входной
  предохранитель → KCD11 → проверенная защита/преобразователь → 5 V вход платы.
  Предохранитель подбирается под проводку и измеренный ток, не по максимуму buck.
  Установить и измерить выход LM2596 **до** подключения ESP32.
- LM2596 и один SMBJ33CA сами по себе не доказывают защиту от автомобильных
  импульсов, переполюсовки и пуска. Нужна отдельная электрическая проверка.
- Не добавлять 120 Ω параллельно штатной автомобильной CAN. Проверить наличие
  терминатора на модуле; измерять сопротивление только на обесточенной цепи.
- Не соединять одновременно USB-питание и питание машины без проверки защиты
  от обратного тока. OBD pin1 не считать универсальным сигналом зажигания.
- Сохранить factory backup, NVS и текущую рабочую конфигурацию. Не делать
  `erase_flash`, не менять partitions. Подсветка пока FIXED: LED связан с 3.3 V.

## 2. Однократная сборка и прошивка

ПК нужен только для подготовки/прошивки. В штатной работе Python, VNCI, ODIS,
телефон и внешний OBD dongle не нужны.

В окружении ESP-IDF5.5.5, каталог `firmware`, сначала собрать listen-only:

Если стандартный менеджер зависимостей не работает, использовать проверенный
[режим локальных зависимостей](docs/development.md#build-from-hash-verified-local-dependencies).
Он сохраняет версии из lockfile; прошивать смесь компонентов разных версий нельзя.

```sh
idf.py -B build-listen -D SDKCONFIG=sdkconfig.listen.generated -D "SDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.listen-only" build
```

Проверить generated config: CAN enabled, TX4/RX5, STANDARD_OBD disabled,
HOST_INJECTION disabled. Выбрать **фактический** serial port платы и прошить:

```sh
idf.py -B build-listen -D SDKCONFIG=sdkconfig.listen.generated -p YOUR_PORT flash
```

Сначала проверить экран/тач на столе. Выполнить калибровку, сохранить настройки,
подождать ≥2 s перед отключением. Убедиться, что NVS восстановилась после reboot.

## 3. Listen-only на машине

При выключенном KCD11 подключить собранное устройство, затем включить питание.
SERVICE STATUS должен отражать CAN state/RX; TX должен оставаться 0.
Отсутствие RX не доказывает неисправность: шина может спать или нужный трафик
недоступен в этой точке. Ошибка CAN/PINS/DRIVER — остановка проверки, не повод
перебирать произвольные GPIO/CAN IDs. При нарушении работы штатных систем
сразу выключить/отсоединить прототип и сохранить наблюдения.

## 4. Автономный OBD

Только после проверки проводки/listen-only собрать standalone и прошить на столе:

```sh
idf.py -B build-standalone -D SDKCONFIG=sdkconfig.standalone.generated -D "SDKCONFIG_DEFAULTS=sdkconfig.defaults;sdkconfig.standalone" build
idf.py -B build-standalone -D SDKCONFIG=sdkconfig.standalone.generated -p YOUR_PORT flash
```

Отключить USB. На неподвижной машине включить зажигание/питание устройства.
Ожидаемый путь: LISTEN → OBD discovery/capabilities/VIN → LIVE, если ECU отвечает.
После старта 1.5 s hardware listen-only, затем standard Mode01/PID00 discovery
на 0x7DF. 0x7E8…0x7EF — standard OBD responders, **не подтверждённые physical
адреса всех VAG-блоков**. Выбранный ECU должен поддерживать RPM.

Проверить RPM, speed=0, coolant, затем другие поддержанные PIDs. Сравнить с
эталоном и записать погрешность/частоту; значение на экране не равно валидации.
Неподдержанные параметры должны быть unavailable/unsupported, не нулём.
MAP — абсолютное давление во впускном коллекторе; MAP−baro — derived boost,
не доказанный VAG charge-pressure DID. Module voltage — напряжение ECU,
не измерение на клеммах АКБ. DQ500/Haldex/steering пока не включены.

## 5. Диагностика и восстановление

На SERVICE STATUS удержание после калибровки (рабочая область ниже заголовка)
запрашивает Mode03 при свежей speed=0. Показываются stored emissions DTC выбранного
ECU, максимум12; коды перебираются каждые2 s. Ноль допустим только после валидного
ответа. Нет clear, freeze frames, расшифровок и сканирования всех блоков.

При потере ответов — bounded retries, затем QUIET без polling. Также QUIET
возможен после120 s свежих RPM=0/speed=0, включая долгий start-stop. Удержание
позволяет retry; обычный CAN-трафик после тихой паузы ≥5 s может запустить discovery.
Поведение нужно проверить физически, не считать его надёжным ignition detector.

**QUIET не отключает питание. После теста выключить KCD11. Не оставлять прототип
на ночь подключённым с включённым выключателем.** Автоматический power-off и
нулевой standby current не реализованы. Телефон нужен только опционально для
существующего временного Wi-Fi редактора экранов, не для получения CAN-данных.
В этой поставке trace — RAM ring96 кадров с C snapshot API, без HTTP-download.

## 6. Что зафиксировать

Commit, preset, hash прошивки, схему/фото проводки, модель transceiver, напряжения,
ток ON/QUIET/OFF, время cold boot→LIVE, RX/TX/errors/dropped/bus-off, поддержанные
параметры, эталонные значения, перезапуск/отключение ECU, NVS/calibration retention.
VIN и реальные traces хранить приватно. Без этих данных не объявлять REAL-CAR PASS.
Не проверять coding/adaptation/security/flash/clear и не отправлять сырые команды.
