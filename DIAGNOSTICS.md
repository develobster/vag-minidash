# Диагностическая лаборатория 0.4

## Запустить

```sh
python diagnostics.py
python diagnostics.py --scenario pending
python diagnostics.py --scenario silent
python diagnostics.py --scenario endless_pending
```

В графическом приложении: **Инструменты → Диагностическая лаборатория (Fake ECU)**.
Можно выбирать сценарии и экспортировать JSON. Все значения синтетические.
VIN `WVWZZZ00000000000` вымышленный. Отчёт помечен `source=fake_ecu`, `vehicle_connected=false`.
Инвентаризация пользователя и приборная панель этими значениями не обновляются.

## Реализованная граница

DiagnosticLab → FakeECU → полные диагностические PDU в памяти.
Нет CAN-кадров, сегментации ISO-TP, подключения к адаптеру, смены сессии,
SecurityAccess/SFD, сброса ошибок, базовых установок или записи кодировок.
Конструктор отвергает транспорт, отличный от FakeECU.

Это небольшая эталонная лаборатория для тестирования поведения, а не полный UDS-стек.
Для будущего реального транспорта по-прежнему рассматривается udsoncan с тестами
совместимости выбранной версии. Библиотека сейчас не установлена и не встроена.

## UDS-чтение

- ReadDataByIdentifier 0x22, один DID на запрос, обязательная ожидаемая длина.
- Проверка положительного SID, отражённого DID и точной длины.
- Отрицательный ответ 0x7F: проверка SID запроса; NRC сохраняется в исключении.
- NRC 0x78: ждать следующий ответ, не повторять исходный запрос.
- P2, P2*, общий deadline; даже бесконечный pending не снимает общий предел.
- Очистка старой очереди перед новым запросом; трасса tx/rx с виртуальным временем.
- Внутренний интерфейс принимает только чтение DID и Mode 01, другие команды отвергает.

Время детерминированное, без sleep. Сценарий «три секунды ожидания» завершается сразу
в реальном времени, с продвижением виртуальных часов. Это не проверка реальных задержек ОС.
Трасса предназначена для ограниченных сценариев лаборатории, не для непрерывной записи поездки.

## Generic OBD Mode 01

Чтение битовых карт 00/20/40/... ограничено восемью страницами. Следующая страница
запрашивается только при наличии флага продолжения. Служебные PID страниц не считаются
измеряемыми параметрами. Отсутствующий PID не запрашивается методом read_pid.

| PID hex | Параметр | Формула для байтов A/B | Единица |
|---|---|---|---|
| 04 | Расчётная нагрузка | A × 100 / 255 | % |
| 05 | Температура охлаждающей жидкости | A − 40 | °C |
| 0C | Обороты | (256A + B) / 4 | rpm |
| 0D | Скорость | A | km/h |
| 0F | Температура впуска | A − 40 | °C |
| 11 | Положение дросселя | A × 100 / 255 | % |
| 42 | Напряжение блока | (256A + B) / 1000 | V |
| 5C | Температура моторного масла | A − 40 | °C |

Наличие этих декодеров не означает поддержку всех параметров автомобилем.
Это не температура DSG, не выбранная передача и не расширенные параметры VAG.
Декодер принимает PDU, уже очищенную транспортом от CAN padding; лишние байты отвергаются.
Discovery возвращает поддержку одного FakeECU; объединение ответов нескольких ECU не реализовано.

## Сценарии

| Сценарий | Проверяемое поведение |
|---|---|
| normal | VIN, поддержка PID, восемь измерений |
| pending | Один запрос, промежуточный 0x78, положительный ответ |
| endless_pending | Остановка по общему deadline |
| silent | Таймаут первого ответа |
| negative | Явная ошибка с NRC |
| wrong_echo | Отбрасывание ответа с другим DID |
| truncated | Отбрасывание обрезанного ответа |

## Проверка

41 тест всего, из них 20 новых методов тестирования диагностики. Проверены числовые
значения/единицы, длины, bitmaps, запрет неподдерживаемых PID и команд записи,
таймауты и отсутствие повторной отправки при pending. Python-файлы скомпилированы.
GUI не проверен визуально в этой среде; CAN/ISO-TP и реальный автомобиль не тестировались.
